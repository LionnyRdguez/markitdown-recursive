
# Zsh Test Suite

Automated tests for MarkitdownRecursive.

The test suite validates the Zsh implementation through unit tests, integration tests and real end-to-end executions.

## Running the tests

From the repository root, execute:

```zsh
./Zsh/tests/run-tests.zsh
```

The runner automatically discovers and executes:

- Unit tests in `unit/`.
- Integration tests in `integration/`.

Each test file runs in an independent Zsh process.

## Requirements

The test environment requires:

- Zsh.
- MarkItDown available in `PATH`.
- GNU-compatible `find` and `sort` with `-z` support.
- `mktemp`, `mkdir`, `mv`, `rm`, `cp` and `cmp`.
- Standard Unix utilities used by the tests.

The end-to-end test requires a working MarkItDown installation.

Most integration tests use mock executables to simulate MarkItDown behavior. This allows error conditions and edge cases to be tested without depending on actual document conversions.

## Fixtures and expected results

### `fixtures/`

Contains controlled input documents used by real end-to-end tests.

These files represent the original source data. Tests must not modify them.

### `results/`

Contains the expected output generated by MarkitdownRecursive and reviewed before being accepted as a reference.

The expected results validate:

- Converted document content.
- Existing Markdown preservation.
- Output filenames.
- Nested directory structure.

The reference files must not be regenerated blindly after a failed test.

When the application or MarkItDown version changes, inspect the differences and verify that the new output represents the intended behavior before updating the references.

## Test isolation

Integration tests create their own temporary directories using `mktemp`.

Mock executables are created inside these isolated environments and added to `PATH` only for the test process.

Temporary files and directories are removed after each test, including when the application receives SIGTERM where cleanup is possible.

The end-to-end test copies the original fixtures into a temporary source directory, so the real application never processes or modifies the repository fixtures directly.
